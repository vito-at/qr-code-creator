# Проверка документов по QR-коду

Отдельный небольшой сайт. Сотрудник создаёт QR-код, вставляет его в документ клиента (бронь, справку, письмо…) и загружает готовый файл. Проверяющий сканирует QR-код и видит **только этот файл**: на странице нет меню, ссылок и кнопок. Другие страницы сайта ему недоступны. Главная и любые неизвестные адреса показывают «Документ не найден». Админка закрыта паролем.

Админка — на узбекском и русском (переключатель вверху; по умолчанию узбекский, для русскоязычного браузера — русский). Служебные надписи у проверяющего («Загрузка…», «Документ не найден») — сразу на узбекском, русском и английском.

## Как пользоваться

1. Откройте `https://<домен>/<ADMIN_PATH>` и войдите по паролю.
2. Нажмите **«Создать»**. Название можно указать для себя, например «Иванов — бронь отеля»: проверяющий его не видит.
3. Скачайте QR-код (**PNG** или **JPG**) и вставьте его в документ.
4. На той же странице загрузите готовый файл (PDF, JPG, PNG или WEBP). С этого момента QR-код открывает файл.
5. Кнопка «Открыть как проверяющий» покажет страницу так, как её увидят при сканировании.

Пока файл не загружен или если документ удалён, по QR-коду открывается «Документ не найден». Файл можно заменить, QR-код при этом останется прежним. На странице документа видно, сколько раз его открывали по QR-коду.

## Как это защищено

- Адрес документа — случайная строка из 22 символов (`/d/3kZmZwQx5yXXu…`), подобрать её нельзя.
- PDF у проверяющего рисуется картинками (pdf.js), поэтому одинаково виден на телефоне и компьютере. Ссылки внутри PDF не кликаются: уйти со страницы некуда.
- Загружаются только настоящие PDF и картинки: тип проверяется по содержимому файла, а не по расширению.
- Вход в админку: общий пароль; заданный в админке и начальный на сервере CRM хранятся только хэшем (scrypt). Сменить пароль можно в админке, и тогда все остальные входы закрываются. После 10 неверных попыток с одного адреса вход блокируется на 15 минут. Cookie входа — `HttpOnly`, `SameSite=Strict`.
- Страницы закрыты от поисковиков (`noindex`).

## Запуск на сервере CRM (как сейчас работает сайт)

Сайт работает на сервере CRM Orient Travel и запускается из её `crm/docker-compose.yml` как сервис `qr-code-app`. Образ собирается прямо из этого репозитория (ветка `main`), а Caddy из CRM отдаёт сайт по домену `hujjat-ipotekabank.uz`. Настройки (адрес, адрес админки, хэш начального пароля) записаны там же, а секрет входа создаётся сам. Поэтому на сервере ничего настраивать вручную не нужно.

- **Как обновить сайт после изменений здесь:** запустите обновление CRM в её репозитории: **Actions → CRM Deploy → Run workflow**. Пересборка CRM подтянет свежий `main` этого репозитория.
- **DNS:** A-запись `hujjat-ipotekabank.uz` должна указывать на IP сервера CRM.
- **Пароль:** начальный пароль задан хэшем в `crm/docker-compose.yml` (`ADMIN_PASSWORD_HASH`). Смените его в админке («Пароль» вверху): новый пароль хранится в папке данных и заменяет начальный.
- **Данные** (база, файлы, пароль, секрет входа) лежат в томе Docker `crm_qrdata`.
- Если репозиторий сделать приватным, сервер не сможет собрать образ. Тогда понадобится ключ доступа.
- **`BASE_URL` зашивается в QR-коды.** После того как документы ушли клиентам, его не меняйте, иначе старые QR-коды перестанут открываться.

## Запуск на отдельном сервере

Если порты 80/443 свободны, сайт запускается со своим Caddy:

```bash
cp .env.example .env      # заполнить DOMAIN, BASE_URL, ADMIN_PASSWORD, ADMIN_PATH
docker compose --profile https up -d --build
```

## Разработка

Нужен Node.js 22.13 или новее (база — встроенный `node:sqlite`).

```bash
npm install
cp .env.example .env      # для локального запуска: BASE_URL=http://localhost:3000
npm run dev
npm test
```

Код: `src/app.js` — все адреса сайта, `src/views.js` — страницы, `src/store.js` — база и файлы, `src/qr.js` — QR-коды, `src/i18n.js` — тексты админки (uz/ru), `public/viewer.js` — показ PDF у проверяющего.
